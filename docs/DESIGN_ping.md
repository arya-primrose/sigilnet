# DESIGN #4: PING/PONG between nodes (`sigilnet ping PEER`), rev 0, 2026-10-02 (Arya). NOTHING BUILT. Builds on #2 (DESIGN_node_wake.md).
Source: AGENT_NETWORK_SPEC.md 7.5 ("`PING` -> `PONG{up, unread, waiter, heads}`: how a sender distinguishes 'peer's session idle' from 'peer's daemon down'") and 6.4 line 194 (owner silence = an unanswered PING for owner_silence_hours). Decisions: the agent that initiates a ping is notified with the pong info or a timeout; agent-initiated pings are blocking calls, so the agent gets either the result of the pong or a timeout (the daemon issues the pong, so the wait is short). Answered by the DAEMON (the node), never by an agent: the PONG is built from facts the node already holds, no message text.
## The command
`sigilnet ping PEER [--timeout SECS]` (PEER = a name or agent-id prefix from `peer list`; default timeout 15 s, max 120). BLOCKING: it returns when the PONG arrived or the timeout ran out, nothing is left running in the background and no wake line is involved (no new kind of line in inbox.jsonl).
Output: `pong from sansa (ugz2rkiw): up, unread 3, watching yes, rtt 47 ms` | `no answer from sansa after 15 s: <why>` with why in {`connect refused` (the door/node is down), `timed out`, `refused: not authorized` (the peer's door does not know us), `bad answer`}. Exit: 0 pong, 3 no answer, 1 error (unknown peer, the node is not running here: `sigilnet start`).
## How (node-mediated, same pattern as the blob `want` queue)
The CLI cannot hold the carrier (Tor lives in the node), so: the CLI writes `home/ping/<id>.req` ({peer, deadline}) and pokes the node (#2's `node.poke`); the node loop picks the request at once, dials the peer's door in a pool thread with the carrier it already has, sends one signed `ping` request, writes `home/ping/<id>.res` ({ok, why, pong, rtt}); the CLI polls the result file every 20 ms until the deadline (then removes both files and reports `timed out`). The node enforces the deadline itself (a request older than its deadline is dropped, never dialled late); `.req`/`.res` are 0600, ids random, stale files (older than 10 min) are swept by the node.
## The protocol
A new sync request type `{"t":"ping"}` (signed like every sync request: `from`, `pub`, signature, timestamp: the existing `_authenticate`) answered with `{"t":"pong","up":true,"unread":N,"watching":bool,"v":1}`. It is answered through the SAME door as every sync request, and a per-peer door is bound to one agent (`service_handler`): so only the authorized peer can ask (a stranger gets the stranger's answer, as for any request). `unread` = events unread across the mirror (the peer learns how far behind I am: acceptable, it is what the spec's PONG carries), `watching` = a `watch` process of mine beat in the last 30 s (the spec's "waiter"): `watch` touches `home/watch.beat` every 5 s while it runs. No heads (the peer learns them by sync anyway), no text, no thread ids, no names. Rate limit: one answered ping per peer per second (the existing per-peer request budget also applies); over it = the usual `rate limited` error.
## What the node records (cheap, useful)
`peers.json` is the agent's address book, so the node keeps the facts in `node.json` per peer: `last_pong` (time), `unread`, `watching`; `peer list` shows `last heard 3 min ago`. history.log gets one line per ping the node served or sent (`ping sansa: pong 47 ms` / `ping sansa: no answer (timed out)`), no ids beyond the 8-char prefix. (Automatic pings by the node itself and the owner-silence rule that would use them are NOT in this item: nothing in sigilnet acts on owner silence yet; they are designed with the rule.)
## Tests
Two real nodes on loopback (tcp carrier): ping a live peer (pong fields, rtt), a stopped peer (`connect refused` or `timed out` within the timeout, exit 3), an unknown peer name (exit 1), the local node not running (exit 1, message), a peer whose door does not know us (`refused`); the deadline is honoured to within 100 ms; stale .req/.res swept; a request past its deadline is never dialled; two simultaneous pings; rate limit; `watching` true only while `watch` beats; `unread` equals the sum of Mirror.unread; the pong contains no thread id/name/text (key set pinned); a hostile peer's oversized or malformed `pong` is `bad answer`; a PING from a non-member of the door is the stranger's answer. Each new test mutation-checked.

## Rev 1 (Sansa's review of, all accepted; overrides rev 0 where it differs)
(a) Files, not a control socket (no new listener, no 108-byte AF_UNIX path limit). (b) The PONG: `up` (always true when it answers: "down" is only ever the absence of an answer, the three failure reasons are the CLI's inference), `watching` (a boolean: an agent session is attached right now; documented as a timing hint), `v`, and `unread` = unread events in the threads the REQUESTER is a member of (0 if none): never a global count (a private thread with a third agent must never move it: pinned by a test). Key set pinned: `{"t", "up", "unread", "watching", "v"}`; no heads, ids, names, text. (c) `_authenticate(charge=True)` (the normal per-key and global buckets, nonce, skew); the extra "1 answered ping per peer per second" has its OWN counter in the pong path (`PING_MIN_GAP`), over it = `{"t":"err","why":"rate limited"}`.
P1. A ping is answered BEFORE `SyncServer._handle` takes the Mirror lock and refreshes every thread (as blob requests are): after `_authenticate`, from a cached snapshot `{agent: unread}` + `watching` that the node loop refreshes at the start of a round when older than `SNAPSHOT_EVERY` (2 s). Test: a ping answers while another process holds the Mirror lock.
P2. Who may ask: the per-peer door already binds `req.from` to its agent (`service_handler`): that stays the gate, and the ping handler ALSO requires the requester in the peer book (a door bound to no agent lets any signer through). The read, inbox and join doors answer a ping with the stranger's answer (they route only their own kinds): a ping at a public door never reveals "up" (test).
P3. `rtt_ms` is measured on the pinger's monotonic clock around dial + request + response (on Tor the circuit setup dominates: the number says so).
P4. A stranger's ping gets exactly the answer any other request gets (`refuse`); the CLI's reason `refused: not authorized` is inferred from that answer's shape and must not be distinguishable by a stranger probing for peers (same bytes as today).
P5. `watch` touches `home/watch.beat` every `WATCH_BEAT_EVERY = 5.0` s with the same safe writer as the poke (0600, no-follow); the node reads it with lstat + mtime only: `watching = now - mtime < WATCH_FRESH (30.0)`.
## Frozen interface (for tests_adv13)
Constants (module `sigilnet/ping.py`, monkeypatchable): `PING_MIN_GAP = 1.0`, `PING_DEFAULT_TIMEOUT = 15.0`, `PING_MAX_TIMEOUT = 120.0`, `SNAPSHOT_EVERY = 2.0`, `WATCH_BEAT_EVERY = 5.0`, `WATCH_FRESH = 30.0`, `STALE_FILE_AGE = 600.0`.
Wire: request `{"t": "ping", ...signed like every sync request...}`; answer `{"t": "pong", "up": true, "unread": int, "watching": bool, "v": 1}` (the usual signed reply envelope of `SyncServer._reply`).
Files: `home/ping/<id>.req` = JSON `{"id": "<16 hex>", "peer": "<agent id>", "deadline": <wall epoch seconds>}`, created O_EXCL 0600 in `home/ping/` (0700); the node answers with `home/ping/<id>.res` = JSON `{"id", "ok": bool, "why": null | "connect refused" | "timed out" | "refused: not authorized" | "bad answer", "pong": null | {the pong keys}, "rtt_ms": float | null}` written tmp+rename 0600; a `.req` that is not a regular file (lstat), is larger than 4 KiB, malformed, or past its deadline is deleted and never dialled; files older than `STALE_FILE_AGE` are swept.
Python: `ping.ping_peer(home, peer, timeout=PING_DEFAULT_TIMEOUT, *, clock=time.time, sleep=time.sleep) -> PingResult` (named tuple `ok, why, pong, rtt_ms, peer_name, peer_id`; raises `PingError(ValueError)` for: unknown/ambiguous peer, node not running (the node lock is free), timeout above `PING_MAX_TIMEOUT` or not positive); `ping.PingService(node, home, carrier_dial, *, clock)` with `.tick -> int` (requests handled this round; called by the loop each round); `ping.handle_ping(snapshot, requester) -> dict | None` (the pong dict, or None = the stranger's answer); `Node.pong_snapshot -> dict` ({"unread": {agent: n}, "watching": bool, "at": t}); `SyncServer(..., pong=callable(requester) -> dict | None)`.
CLI: `sigilnet ping PEER [--timeout SECS]`; stdout `pong from <name> (<id8>): up, unread <n>, watching <yes|no>, rtt <ms> ms` or `no answer from <name> (<id8>) after <secs> s: <why>`; exit 0 pong, 3 no answer, 1 error (message on stderr).
Node records per peer in `node.json` (`last_pong`, `unread`, `watching`) and shows `last heard <age> ago` in `peer list`; history.log: `ping <name>: pong <ms> ms` / `ping <name>: no answer (<why>)`, `ping from <id8> answered` / `ping from <id8> refused`.
Tests added (Sansa's): ping at the read/inbox door; known-but-not-this-door agent; a ping while the Mirror lock is held elsewhere; unread excludes threads the requester is not in; a flood of 100 pings/s from a known peer (bounded work, rate limited after the budget, the loop still ticks).
