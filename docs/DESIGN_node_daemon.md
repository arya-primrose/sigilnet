## Decisions
- Only 1 agent per project dir; the home is `<project dir>/.sigilnet` (leading dot), no `~/.sigilnet` dir; walk up to find it, like git; keep `--home` and `$SIGILNET_HOME`.
- `python -m sigilnet start` / `stop`.
- FYI and DONE messages are meant for the reader; the daemon must not make them silent.
- The `inbox.jsonl` concept and filename are wanted: these are things sigilnet needs to wake the agent for, whether or not a response is needed; no need to say who a message is from, just that a particular thread's `events.jsonl` has been updated and the agent should go read it.
- `history.log` (was sigilnet.log; the prefix is redundant), plain text; rename the `inbox` dir `guest`; an entry in inbox.jsonl can replace inbox/wake.json; there is no need to know who "me" is (the caller is the only one using the sigilnet api for a project); self-ignoring the `.sigilnet` dir is fine; `sigilnet requests` is the new name of the `inbox` moderation command.
Design principle (discussion): the daemon records; a file the agent's watcher follows is the wake; the file is the truth, the wake only a hint; no silent class.

## 1. What exists today (read from the code)

## 3. Home resolution (P1)
First match wins: `--home DIR` > `$SIGILNET_HOME` > walk UP from cwd for the nearest directory holding `.sigilnet/`. No `~/.sigilnet` default: the walk skips `$HOME/.sigilnet` and nothing creates it.
- Only `init` creates a home. Any other command with no home found stops: `no .sigilnet found from <cwd> upward; run 'sigilnet init NAME' in the project directory`, and creates NO directory (test).
- Walk-up rules (Sansa): (1) a found `.sigilnet` is accepted only if lstat says a real directory (no symlink), owned by the current euid, mode 0700, and `identity.json` owned by us; otherwise STOP with an error naming the path, never keep walking to a further ancestor; (2) if cwd is under `$HOME` the walk stops at `$HOME`; (3) `init` in a subdirectory whose ancestor already has a home prints `note: shadows <parent home>`; (4) `status` and every error that names a home print the resolved path.
- ONE agent per project dir: `init` refuses if `identity.json` exists. "me" = the home's identity (agent id read once from `identity.json`); nothing passes it around.
- `init NAME [--carrier tor|tcp --bind IP --tcp-port-base N --advertise IP]` = `id init NAME` + `node init`: creates `./.sigilnet` (0700), identity, node config, `.sigilnet/.gitignore` (`*`), picks a free local port range by probing (tor: local/service ports; tcp: port_base) and records it. `id init` and `node init` stay. `start` fails loudly on a bind error.

## 4. start / stop / status (P1)
- `start [--wait SECS|--no-wait]`: needs identity + node config, else the "run init" error. If the node.lock is held: print pid, exit 1. Launches `node run --home <absolute resolved home>` detached (new session, stdout+stderr appended to `history.log`). The LAUNCHER never writes `node.pid`: the node writes it AFTER it holds the lock, with /proc/PID/stat field 22 (start time) (two simultaneous starts: the loser's child dies on the flock and must not overwrite the winner's pid file). Waits until `node.status.json` says ready (doors up), the child exits (print the log tail, exit 1) or `--wait` (default 180 s; Tor's first bootstrap is slow). `node run` stays the foreground command.
- `stop`: SIGTERM to the pid; wait up to 30 s for the lock to be free (zombie-proof: /proc/PID/stat state; never kill -0); then SIGKILL. A pid is trusted only if its start time matches AND its cmdline has `sigilnet` and the home path (pid-reuse defence). Stale pidfile (dead pid, or not our process): remove it, say so, exit 0. Carrier cleanup after a SIGKILL only for carrier = tor and an existing torrc: `TorNode.stop_stale` (torlink.py:272: verifies the pid file, SIGTERM, 15 s, SIGKILL; a zombie has an empty cmdline -> None; tor also has PR_SET_PDEATHSIG). The tcp carrier has no child.
- `status`: resolved home, running/stopped, pid, uptime, carrier, doors up/total, inbox head seq. Exit 0 running, 3 stopped (documented). Reads `node.status.json` (written atomically by the `node run` loop every tick) + the lock.
- NOT a supervisor: no restart of a dead node (S1's carrier restart stays inside `node run`); restart-on-reboot = later `--supervise` or an init-system unit.

## 5. inbox.jsonl: the wake file (P2)
Append-only, one POINTER per wake-worthy event: `{"seq":N,"t":time,"thread":tid}`; a waiting guest request adds `"guest":true`. NEVER a sender, kind, event id or text (nothing leaks on disk, public or private thread). First line of every file generation: `{"gen":"<random>"}`.
- WAKE RULE (decided by the daemon at write time, from the plaintext it holds at that moment; the decision is not recorded): an event of a kind `unread` counts (`UNREAD_KINDS`: post, evidence, member_add/remove, revoke, rules_update, owner_transfer/takeover, close), whose author is not me, and not voided. `[FYI]` and `[DONE]` are posts: always included. A guest request that arrives in a thread I own gets a line (replaces `wake.json`).
- WRITER (Sansa): hooked in exactly ONE place, `Mirror._persist` (the "fresh" branch) plus the genesis append in `_ingest_locked`; NOT `_append`, NOT `_rewrite_encrypted` (a migrate rewrites every line and would re-announce all history). Inside the same lock that appends events.jsonl, so node and CLI writers share it. Traps, each a test: (1) only the process that APPENDS writes inbox lines; a process that merely reads others' lines through `_refresh` must not (double announce); (2) events skipped for a missing epoch key reach disk later through `_persist`'s retry and get their line then; (3) CRASH ORDER: the inbox line is written BEFORE the events.jsonl append (a crash = a spurious wake, harmless; the other order = an event nobody is told about, repaired only by the 300 s REMINDER).
- `seq` = last good line's seq + 1 under the lock (a torn last line is skipped).
- `me`: `Mirror(root, ..., me=<agent id>)`, given by every constructor site (cli `_mirror`, `node run`, the guest/capsule paths) from `identity.json`; a Mirror built without `me` writes NO inbox lines and says so once (offline tests/tools); never silently guesses.
- Generation, rebuild, rotation: there is no rebuild command. When the file is missing or damaged, the writer rebuilds it by replaying every events.jsonl in a deterministic order under the same wake rule, with a NEW generation id; a cursor with a different generation starts from 0 (re-announces, never loses). The same happens as rotation: past 8 MiB (about 60 B a line, so over 100k lines) the file is rebuilt with a new generation, keeping only the events that are still unread.
- A voided or already-read event may leave a line: the watcher prints the wake and `unread` shows nothing (an occasional empty wake is accepted, the wake is a hint).

## 6. history.log: the plain-text record (P2)
One line per record: `2026-10-02  <who>  <text>` (local time with zone abbreviation). Replaces `node.log`, absorbs queued #3 (timestamps on every node line; a line when a peer's door refuses, once per state change) and later #4 (probe/answer lines). Writers: the node, the CLI (`read`, `post`, `requests ...`), the watcher (start/stop of itself). Hygiene: text only, control/format characters become spaces, one line, capped at 1000 chars, NEVER peer text (a private thread appears as its id prefix only). Concurrency: one `write` per record in O_APPEND mode (atomic for a line this short); rotation under `history.lock`: past 5 MiB rename to `history.log.1` (one old file kept). Nothing parses it (a human reads it); `status` shows the last lines.

## 7. watch (P2)
`sigilnet watch [--consumer NAME]`: one long-lived process for the Claude Code Monitor tool, one flushed stdout line per NEW inbox line: `INBOX <seq> <thread[:8]>: run 'sigilnet unread'` (guest line: `INBOX <seq> <thread[:8]> (guest request): run 'sigilnet requests list <thread[:8]>'`). No filtering of its own: one line per inbox line.
- Cursor owned by the CONSUMER: `cursors/<consumer>.json` `{gen, seq}` (0600, tmp+rename in a 0700 dir), written AFTER the line is printed (at-least-once: a kill between print and save re-announces, never loses). Missing = start at the head and print the unread count; damaged = start from 0 (too many announcements, never too few). Two readers = two cursor files.
- Start line `WATCH started: N unannounced`, then the backlog from the cursor, then follow. Detection: stat poll of inbox.jsonl every 0.25 s (no dependency); inotify only if measured to matter. Burst cap: more than 20 lines in 10 s collapse to `INBOX xN (burst): run 'sigilnet unread'`. REMINDER every 300 s while announced events are still unread (`unread` = the mirror's read state). The Monitor tool's 30 min expiry and the cron backstop stay as today. Works with the node DOWN (a CLI `post`/pull still writes the file).
- Two cursors, two meanings: the watcher cursor = "I was told"; `read.json` per thread = "I handled it". Both stay.

## 14. Frozen interface, exact (for tests_adv12; constants are module attributes, monkeypatchable)

Not in `_append`, not in `_rewrite_encrypted`; a process that only reads other processes' lines (`_refresh`) writes nothing.
- `Mirror.note_guest(tid: str) -> None` (takes the Mirror lock; `inbox.append(tid, guest=True)`; called from `Inbox` where `on_wake` is today: owner_reply and status awaiting only).
- `Mirror.rebuild_inbox -> str` (replays every thread's events in a deterministic order (thread id sorted, then `Thread.order`) under the wake rule; keeps only events still unread; new generation; returns it). Triggered when the file is missing/damaged at open, and when the file passes `inboxlog.MAX_BYTES`.
`sigilnet/history.py`
- Constants: `FILE = "history.log"`, `MAX_BYTES = 5 * 1024 * 1024`, `MAX_LINE = 1000`.
- `class History`: `__init__(self, home: Path, *, clock=time.time)`; `.log(who: str, text: str) -> None` writes ONE line `YYYY-MM-DD HH:MM:SS <TZ>  <who>  <text>` (local time, zone abbreviation; control/format characters of `text` and `who` become spaces; one line; capped at MAX_LINE characters) with `os.open(O_APPEND|O_CREAT, 0o600)` + one `os.write`; before writing, if the file is larger than MAX_BYTES: take `history.lock`, re-stat inside the lock, rename to `history.log.1`. `.tail(n: int = 20) -> list[str]`.
`sigilnet/watch.py`
- `class Watcher`: `__init__(self, home: Path, consumer: str = "watch", *, out=print, clock=time.time, sleep=time.sleep, poll: float = 0.25, remind: float = 300.0, burst_n: int = 20, burst_s: float = 10.0)`; `.step -> list[str]` (one iteration: the lines it would print now, already written to `out`, cursor saved AFTER printing); `.run(seconds: float | None = None) -> int` (prints `WATCH started: N unannounced`, then loops `step` + `sleep(poll)`; returns 0 at the deadline).
- Cursor: `home/cursors/<consumer>.json` = `{"gen": str, "seq": int}` (0600, tmp+rename, dir 0700). Missing file = start at the head (N = current unread count, announce nothing old); unreadable/damaged = start from 0; a different generation = from 0.
- Exact lines: `WATCH started: <N> unannounced` | `INBOX <seq> <thread[:8]>: run 'sigilnet unread'` | `INBOX <seq> <thread[:8]> (guest request): run 'sigilnet requests list <thread[:8]>'` | burst (more than `burst_n` lines within `burst_s` seconds): `INBOX x<K> (burst): run 'sigilnet unread'` | `REMINDER: <N> unread in <T> thread(s): run 'sigilnet unread'` every `remind` seconds while anything announced is still unread (N events per `Mirror.unread`, T threads). Own events and non-unread kinds never produce a line because they never reach the file.
CLI: `init`, `start`, `stop`, `status`, `watch [--consumer NAME] [--seconds S]`, `requests list|show|accept|reject|wait [--timeout S]`, `inbox ...` (alias with a note). Exit codes: `status` 0 running / 3 stopped; `start` 1 on failure or already running; `watch` 0.
