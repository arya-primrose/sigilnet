## 1. What format 2 IS (the whole difference from format 1)
A format-2 thread is a format-1 thread whose genesis and every event carry `v` = 2, plus exactly two extensions. NOTHING else changes: same genesis body keys, same rules, same admin kinds and bodies, same derivation, same envelope, same capsule.
1. **Extension kinds**: an event kind named `x-<name>` (`X_KIND_RE = x-[a-z0-9][a-z0-9._-]{0,47}`, fullmatch) is legal ONLY in a format-2 thread. Body = any JSON object that canonical JSON can carry (event size cap decides). Author must be owner/admin/member (not guest, not observer). It is never an admin kind: no cosigs, no `admin_ref` effect, never changes membership, rules, validity or `head`; it is a normal leaf event in the DAG (needs `parents`, `seq`, `admin_ref` like a post). Stored, synced, relayed, signed, NEVER interpreted by this release.
2. **Extension key `x`** in the body of `post`, `digest` and `evidence` (not in admin kinds, not in a guest admission request): optional, a JSON object, canonical size <= 4096 bytes, ignored by this release.
Every other unknown kind stays refused (a node cannot tell an admin kind from an inert one). A kind's meaning never changes after release.

## 2. Rules in code (one place each)
- `version.FORMATS = (1, 2)`; `event.SUPPORTED = (1, 2)`; `event.V` stays 1 as the default for old callers.
- `event.check_structure(ev)`: `v` must be 1 or 2 (int, not bool); kind must be in KINDS, or (v == 2 and X_KIND_RE.fullmatch(kind)). So a v1 event named x-foo is "unknown kind" exactly as before.
- `Thread.format = genesis["v"]` (genesis body checks unchanged). `_accept` and `add_many` (disk load) refuse a non-genesis event whose `v` != `Thread.format`: "format mismatch" (new nodes and 0.1.x agree: both refuse). An orphan (arrived before its genesis) is re-ingested through `accept` when the genesis arrives, so it is re-checked there.
- `_body_problem`: `x` allowed on post/digest/evidence only when format == 2, dict, canonical size <= 4096, and not together with `guest`; an `x-` kind falls through the role gate (member roles only) and returns None. `_evidence_problem`: the two embedded events must have `v` == the thread's format (a cross-format pair is not evidence).
- `_classify_one` / size caps / buckets: x- kinds are charged like post/digest/evidence: `mirror` rate limit and `recv` bucket kinds become `OWN_RATE_KINDS = post, digest, evidence, x-*`; `MAX_STORED` counts them as it counts everything stored.
- Wake/unread: `UNREAD_KINDS` is unchanged, so an `x-` kind is never unread and never wakes (quiet by construction). `show`/`history` print it as `(x-name) {json}` through the existing generic line (no preview of the body beyond 160 chars).
- Builders: `make_event(..., v=1)`, `make_genesis(..., fmt=1)`, `Writer` uses `thread.format` for every event it builds (so a format-2 thread's events are v 2 automatically). `new` gets `--format N` (default 1, for tests and for the first format-2 threads); `Writer.ext(name, body)` builds an x- event (library, plus `sigilnet post --kind x-name --json '{...}'` is NOT added: nothing writes x- kinds yet except tests and the library).
- Envelope: the envelope version stays 1 for every thread (it wraps one event and has its own exact set; the inner event carries the thread's format). This is a CHANGE from design rev 3 section 5a.3 ("an envelope version follows the thread format"): nothing in the envelope depends on event semantics, and leaving it alone keeps one frozen layer fewer. A format 3 can revisit.
- Capsule: layout frozen (v 2); the joiner learns the format from the genesis it pulls. `capsule accept` of a thread the node cannot read is refused at the pull (gating text below), nothing to add to the capsule.

## 3. Gating and refusals (stage 2 already built the server side)
- Serving: a thread is served only to peers whose declared `formats` contain its format (undeclared = [1]); stage 2 text path unchanged. With FORMATS = (1, 2) a new node serves format 2 to new nodes only, and tells a 0.1.x or a 0.2.0 peer ("thread uses format 2: upgrade sigilnet"-style one sentence from `version.refusal`). 0.2.0 nodes declare formats [1], so they are gated cleanly (a test against a 0.2.0 tree).
- Pull side: when a pull gets events refused as format mismatch or unsupported version, the job note says "N events refused: format X" (counts by reason), so the operator of a new node sees it.
- Follow expiry (`autorotate._verify`): an automatic follow whose thread never arrived and whose last peer job error says needs a newer format is logged "auto-follow: a follow expired (refused: needs format 2)" instead of "never arrived"; `peer list` shows the refusal text already (stage 2).

## 4. Rotation = the upgrade path
- `rotate_thread(..., fmt=None)`: default KEEPS the thread's format (also for the 80 % auto-rotation); `rotate THREAD --format 2` is the explicit owner decision, never automatic.
- Before a format change the owner node checks every non-owner member (observers included) in `peerver`: a member whose recorded declaration has `formats` without the target, or who is `legacy`, or who is unknown, REFUSES the rotation with the list ("members that cannot read format 2: sansa (sigilnet 0.2.0), the-observer (unknown)") unless `--force-format`. `--close` together with a format change is refused unless every member declared the format (never with --force-format).
- Downgrade is not a thing: `--format` below the thread's format is refused (a thread never loses a format; a format-1 thread cannot come from a format-2 one, because x- events would be lost).
- The owner's node is a Thread-format-2 writer for the new thread; the first post `[ROTATED-FROM]` and everything the Writer builds there is v 2.
