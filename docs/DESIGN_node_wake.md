# DESIGN #2: the node wakes at once (interruptible loop), rev 0, 2026-10-02 (Arya). NOTHING BUILT.
Go given 2026-10-02: do #2, #3 and #4; #1 is left open. Live test 5 (r38c_p2) measured the cost: peer post -> wake line = 1.0-2.9 s on TCP (uniform), because `noderun.run` ends every round with `time.sleep(TICK)` (TICK = 2.0 s) and both ends wait for it: the author's node only notices a local post at its next tick (`Node.tick` -> `m.refresh` -> a `notify` job), the receiver's `on_notify` sets the pull job due "now" but nothing runs it before the next tick.
## Change (noderun.py loop + node.py, no protocol change)
1. A node-wide `threading.Event` `wake` owned by `Node` (`node.wake`). The loop replaces `time.sleep(TICK)` by `node.sleep(TICK)`: waits up to TICK in slices of POLL (0.05 s), returns early when `wake` is set (then clears it) or when the poke file changed (below). Never longer than TICK: a missed wake costs at most the old behaviour.
2. `Node.on_notify` sets `wake` after it made the pull job due (it already does `j["next"] = ...`). A rejected notify (unknown agent) sets nothing (a stranger cannot spin the loop).
3. Local events: the CLI (`post`/`ask`/`done`/`new`/capsule steps: everything that appends to a mirror) cannot call into the node process, so `Mirror` touches `home/node.poke` (an empty file, mtime = now) whenever it appends events (`_persist`, same place as the wake line, under the same lock). The node loop compares `st_mtime_ns` of `node.poke` every POLL slice (one stat per 50 ms = negligible); a change = wake. The mirror's own writes by the node process also touch it (harmless: the next round finds nothing to do).
4. Floor: the loop never runs two rounds closer than MIN_ROUND (0.2 s) so a burst of pokes (a 482-request fetch, a flood) cannot make it spin; MIN_ROUND, POLL and TICK are module constants.
5. A round that is woken early does exactly what a normal round does (`m.refresh`, plan, due jobs): no new code path, no new state; the 2 s timer stays as the backstop.
## Expected effect
post -> node tick wait (0..2 s) -> notify RPC -> receiver tick wait (0..2 s) -> pull RPC -> ingest -> wake line becomes: poke detected <= 50 ms -> notify RPC (~45 ms on TCP LAN) -> `on_notify` wakes the loop at once -> pull RPC (~45 ms) -> ingest -> inbox line. Target: post -> wake line under 0.5 s on TCP (LAN); on Tor the two circuit round trips dominate (~1-3 s each way, previously +4 s of ticks).
## Risks to review
(a) `node.poke` is written by every mirror append in every process: a failing touch (read-only fs, no space) must never fail the append (best effort, caught). (b) The loop's 50 ms stat: an unreadable/missing poke file = "no change". (c) MIN_ROUND vs the soak's assumptions (jobs are due-time based, unchanged). (d) Anything that relied on exactly 2 s rounds in tests: `TICK` is a module constant; tests that monkeypatch it keep working; add tests with an injected clock/sleep.
## Tests
Loop wakes within POLL after an `on_notify` for a known agent and does NOT for an unknown one; wakes after a `Mirror` append in another process (poke); never sleeps longer than TICK when nothing wakes it; MIN_ROUND floor under a stream of 1000 pokes (rounds counted); a failing poke touch does not fail the append; two real nodes on loopback: post -> `inbox.jsonl` line within 1 s (was 1-3 s); the unit tests of Node and the soak stay green. Each new test mutation-checked.

## Rev 1 (Sansa's review of, all accepted; overrides rev 0 where it differs)
W1. The 5 s floor `MIN_REPULL`: `Node.on_notify` no longer schedules a pull no earlier than `started + MIN_REPULL`. Replaced by a token bucket per (peer, thread) kept in memory: `PULL_BURST = 3` tokens, refilled at `PULL_REFILL = 1.0` token/s. A notify that makes the pull due spends a token and sets the job due NOW; with no token the job is due when the next token is available. Bound: at most PULL_BURST then 1 pull/s per (peer, thread) from a KNOWN peer flooding hints (each a few requests against the sender's per-key budget: it self-limits through "rate limited" backoff). The target is stated for an ISOLATED post (and up to 3 in a burst): post -> wake line < 0.5 s on TCP LAN. `MIN_REPULL` stays as a name only if something else uses it (grep; else removed).
W2. The poke is an EXPLICIT Mirror parameter: `Mirror(..., poke: Path | None = None)` (keyword-only), set only by `home.open_mirror(home, me, *, poke=True)` to `home/"node.poke"`; never derived from the mirror root. Touch = `os.open(path, O_WRONLY|O_CREAT|O_APPEND|O_NOFOLLOW, 0o600)` + one `os.write(b"x")`, errors swallowed (best effort), done AFTER the events.jsonl append in `_persist` (the wake LINE stays before it; the loop's `m.refresh` blocks on the Mirror lock either way, so both orders are safe). The one-factory grep test also covers `poke=`.
W3. A poke appends one byte (so size changes, not only mtime); when the file passes `POKE_CAP = 4096` bytes the next poke truncates it first. The loop compares `(st_mtime_ns, st_size, st_ino)`; a missing/unreadable file = no change.
W4. `Node.on_notify` sets `node.wake` ONLY when it really made a job due: not for an unknown agent, and not when "all leaves are already stored" (known leaves = no wake).
W5. The NODE's own mirror does NOT poke (`open_mirror(..., poke=False)` in `noderun.run`): a 10k-event first sync would be a poke per event. Instead the loop wakes itself ONCE after a pull job that ingested something finished (`Node._run_queued` sets `node.wake`; the Event coalesces any number into one wake), so `Node.tick` then sends notify to the OTHER peers (gossip with 3+ agents). Test: 10k ingests through a node produce a bounded number of rounds.
W6. Order: the loop CLEARS the event at the start of a round (`Waker.round_started`), BEFORE the round's work: a notify arriving during the round re-sets it and the next wait returns at once (tested). An idle node wakes 20 times a second for the one stat (no inotify in the stdlib): said here.
## Frozen interface (for tests_adv13; constants are module attributes, monkeypatchable)
`sigilnet/wake.py`: constants `TICK = 2.0` (the backstop: `noderun.TICK` is the same name and the loop reads it from noderun), `POLL = 0.05`, `MIN_ROUND = 0.2`, `POKE_CAP = 4096`. `poke(path) -> None` (the safe writer above; never raises). `class Waker`: `__init__(self, poke_path, *, clock=time.monotonic, sleep=time.sleep, poll=None, min_round=None, tick=None)` (None = the module constants at call time); `.event: threading.Event`; `.wait(timeout=None) -> str` = "wake" (the event was set), "poke" (the poke file's (mtime_ns, size, ino) changed since the last look), or "timeout" (nothing for `timeout`, default TICK); it never returns before `min_round` has passed since `round_started` and never waits longer than the timeout; `.round_started -> None` (clears the event, records the poke stamp and the round start time).
`sigilnet/node.py`: `Node.wake: threading.Event` (the Waker's event is the node's: `Waker(..., ).event is node.wake` is arranged by `noderun`); `PULL_BURST = 3`, `PULL_REFILL = 1.0` module constants; `Node.on_notify` as W1/W4; `Node._run_queued` sets `self.wake` after a pull that ingested events.
`sigilnet/mirror.py`: `Mirror(..., poke=None)` as W2.
`sigilnet/home.py`: `open_mirror(home, me, *, poke=True)`.
`sigilnet/noderun.py`: the loop is `waker.round_started` ... round ... `waker.wait(TICK)`.
