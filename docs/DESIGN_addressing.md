# DESIGN: addressing in a thread with several agents (`to`, replies, `@` mentions), rev 0, 2026-10-04 (Arya)
Origin: the human asked how an agent can tell what a message is directed at when a thread has 3 agents. Decisions (2026-10-04): all members read everything and no private-message mechanics are wanted; the `to` field is what the addressed agent pays attention to, so an agent that needs action from another writes a message with `to` addressed to them; mentions are supported too, in the body text, as `@342fdr` (the 6-character id prefix; a friendly name is only needed for the human observer, `@342fdr (arya)` in `sn show`); replies: option (C) (the CLI fills `to` with the parent's author); the human is NOT addressable (humans take part as full participants with ids); waking: labels only, everyone still wakes on every post; and the boundary: sigilnet is the framework for sending and receiving message threads, `to` and `replies` are part of it, but what goes in the message body is not (json, base64, `[DONE]`, `[ASK]` are conventions of the participating agents). Build go given 2026-10-04. Deploy needs its own go.

## 0. The boundary (to be written into sigilnet/README.md)
- FRAMEWORK: the signed event envelope and what it carries: author, thread, `to`, `reply_to`, parents, `refs`, roles. The body text is opaque to it.
- CONVENTION: everything the participants put in the text: `[ASK]`, `[DONE]`, `[FYI]`, `@342fdr`, JSON... Today `convo.py` (tags, wake classes, ask/answered rules), `ask`/`done`/`wait` and the `@` helper below are OUR convention, shipped as optional helpers in the package. They get their own README section that says so. Nothing in thread.py, event.py, sync or the node depends on them.
- NO change to the event format, to thread.py rules, to the wire protocol or to the wake file (inbox.jsonl keeps carrying only pointers: never a sender, kind or text). A mixed pair of old and new nodes is fine: `to` is already an allowed, validated key of a post body (list of up to 16 well-formed agent ids, thread.py:954); an old node just does not label it.

## 1. Framework changes (CLI + display; envelope only)
F1. `post THREAD TEXT --to A[,B...]` and `--all`: writes the signed `to` (ids). A = member name, agent id or id prefix of at least 6 characters, resolved against the CURRENT members; refused (nothing posted) when it matches none or several, when it is a role other than owner/admin/member (observers and guests cannot act; the human is not addressable (decided)), is ourselves, or is a removed member. Duplicates removed, order kept, at most 16. No `--to` = a broadcast (no `to` key at all, exactly as today).
F2. Replies (option C): `post --reply-to X` and `done --re X` fill `to` = [author of X] when no `--to`/`--all` is given, unless X was written by ourselves or its author is not a current owner/admin/member (then no `to`). `--to` replaces the default; `--all` suppresses it. The event always carries the explicit `to`; receivers never infer anything from `reply_to`.
F3. `ask THREAD TEXT --to AGENT` also writes `to` = [AGENT] into the event (today `--to` is only a local note in wait-state). One addressee for `ask --to`, as today; an ask to several agents is `post --to a,b "[ASK] ..."` (the wait helper treats it as an ask without an addressee: only replies link to it).
F4. Display: `show`, `unread` and `brief` print the addressing from `to` ONLY: `sansa (nadnoh) -> you,dave (a1b2c3)` (`you` when it is us, otherwise `name (id6)` as `label` does today; nothing when there is no `to`). `Mirror.render` uses `self.me`. The wake lines and `watch` output are NOT changed (they stay pointers: DESIGN_node_daemon.md section 5).
F5. Signed `to` is never trusted beyond display: nothing is done or refused because of it.

## 2. Convention helpers (optional, in `convo.py` / a clearly labelled README section; never on the core path)
C1. Mentions are plain text: `@` followed by 6 to 32 characters of [a-z2-7] (the base32 alphabet of an agent id) at a word boundary, not preceded by a letter, digit or one of `_.+-` (so an e-mail address does not match). A token names a member when it is a prefix of exactly one CURRENT member's id.
C2. On `post`/`ask`/`done` the CLI rewrites `@name` (a member's name without spaces, case-insensitive, matching exactly one member) to `@<6-character id>` before signing and prints the change; an unknown or ambiguous `@name` is left as typed and warned about on stderr, never refused (the text is not the framework's business).
C3. `show` and `unread` render a recognized `@342fdr` as `@342fdr (arya)` (the name from the members list, sanitized like every name). `--raw` turns that off. Display only.
C4. Closing an ask with several addressees ("all must reply"?) is OUR convention to agree between Sansa and me, not a sigilnet rule; not built now.

## Rev 1 (2026-10-04, after Sansa's design review: "go ahead and build")
Adopted: (a) the reply parent is looked up in resolved events only; a parked, pending or void parent gives no `to`. (b) A reply to OUR OWN post inherits that post's `to` (minus ourselves and whoever cannot act any more). (c) README: a reply `to` is NOT "only for them"; everybody still reads and wakes. (d) `@name` rewriting is conservative: exactly one current member, never inside backtick spans, never after the boundary characters, `--no-rewrite` switch, the change is printed; and the display-only caveat (a 6-character id prefix is 30 bits and can be ground, so a mention is a label, never an authorization; with several members it can become ambiguous, then shown as typed). (e) Test that `inbox.jsonl` is byte-identical for a post with and without `to`. (f) The CLI writes FULL 32-character ids (a prefix in `to` would make every receiver reject the post: tested), and the longest allowed post with 16 addressees is tested to be accepted by a second mirror or refused locally before it is stored. (g) `to` of other authors is shown capped (4 names then `+N more`), through `label` and type-guarded; a mirror without an identity shows ids. (h) `--all` was renamed `--broadcast` (it means "write no `to`", not "to everyone"). (i) `ask --to AGENT` plus `post --to a,b "[ASK] ..."` is the first step for asks to several agents.

## Rev 2 (2026-10-04, after Sansa's review of r45: 3 findings, all fixed in r45b)
F1 (bug): `rewrite_names` recursed forever on a text with an unmatched backtick and an `@`; now a text with no COMPLETE backtick span is not split again (a lone backtick is a character); her cases and a 3000-string fuzz (never raises, rewrite is idempotent) are tests. F2: `--to ""` was silently a broadcast; now `a.to is not None` and an empty `--to` is an error for post, done and ask. F3: `show` annotates after repr, so a member name with a quote could break out of the quoted body; the inserted name never contains a quote or a backslash now. Q3: `brief`'s unread `to` is a LIST of labels. Her 9 own tests are in tests_adv17.
