# Design: encrypted envelopes for PRIVATE threads (step "3" in the human's list). DRAFT 2026-09-30, for Sansa's review BEFORE code.
Go given: envelopes are fine. Spec 7.1 / 8 say: thread key per epoch, ECIES-sealed delivery, AEAD with AAD = thread||epoch, the whole signed event inside the ciphertext.
Already in the code: `thread.state["epoch"]` bumps on `member_remove` (thread.py ~l.1091). So NO thread.py change is needed: the thread state machine keeps working on PLAINTEXT signed events; encryption is a wrapper at two boundaries (transport, disk).

## What envelopes do and do not give (say this plainly in the README)
Gives: (1) confidentiality on any carrier that is not a member (a future relay, store-and-forward, a stolen backup of the mirror directory, a log); (2) key-gated epochs: a removed member cannot decrypt anything after the rotation even if it still reaches a door; (3) author, kind, parents and exact length are hidden from non-members (padding).
Does NOT give: protection against a compromised host that holds the keyring (keys sit next to the data: same disk); forward secrecy per message; hiding ids/epochs/rough size from a carrier; anything for PUBLIC threads (spec 5.1: signed, plaintext). Over Tor between authorized peers the circuit is already encrypted: envelopes are for what Tor does not cover.

## Objects
- `ThreadKey` K_e: 32 random bytes per (private thread, epoch). Keyring file `keys/<thread>.json` (0600, flocked, atomic): {"<epoch>": base64 key}. The owner makes K_0 when it creates the thread (`new`), K_{e+1} when it sees epoch e+1 in the state (after its own member_remove).
- Envelope (canonical JSON): {"v":1,"th":<thread id>,"ep":<epoch int>,"n":<b64 12-byte random nonce>,"c":<b64 ChaCha20-Poly1305(K_ep) of canon(signed event) padded to a 256-byte bucket>}; AAD = "sigilnet/v1/env\0" || th || ep (4 bytes BE). Random 12-byte nonces are safe below 2^32 envelopes per key; rotate long before.
- The genesis stays PLAINTEXT (its hash is the thread id and every capsule/peer entry names it; it carries members' names and keys: stated). Everything else in a private thread is an envelope on the wire and on disk.
- Epoch of an envelope = the epoch of the event's `admin_ref` state (what the AUTHOR knew). The opener tries exactly that epoch's key (an event in flight across a rotation still opens: the old key is kept forever).

## Boundaries
1. Transport (sync.py): SyncServer `get` for a thread that has a keyring returns envelopes instead of events (genesis raw); `list`/`summary` unchanged (ids are hashes of the plaintext events: the carrier learns counts and ids, nothing else). Client `pull` opens each envelope with its keyring, then checks `event_id(ev) in asked` and ingests as before. Unknown epoch key -> counted as `need_key` (not junk), the node schedules a `key` job. A plaintext non-genesis event for a thread WE hold a keyring for is REJECTED (downgrade: a peer must not make us accept or send plaintext).
2. Disk (mirror.py): a codec hook on the thread's `events.jsonl` lines: encode line = envelope JSON, decode on load; lines without `"v":1,"th"` are plaintext (migration: old plaintext threads keep loading; `envelope enable THREAD` (owner) creates K_0 and rewrites the file encrypted). Missing key at load = the thread loads as LOCKED (listed, not readable) instead of crashing. `read.json`, `awaiting.jsonl` (public threads only) untouched.
3. Keys to members (no chain change, no on-chain key material):
   a. JOIN (capsule): the signed `joined` answer carries `keys`: [{ep, sealed}] = ALL epochs the owner holds, each ECIES-sealed to the joiner's kex key (ephemeral X25519 + HKDF-SHA256 + ChaCha20-Poly1305, AAD = "sigilnet/v1/keyseal\0" || thread || epoch || recipient id). The joiner's code installs them only after the signature check. The capsule gets a field `enc` (bool); `describe` prints "events are encrypted" or "NOT encrypted" from it (structured, not prose).
   b. ROTATION: a new sync op `key` {thread, epochs:[..]} (signed, audience-bound like every sync request) answered only to a CURRENT member (role anything incl. observer) with their sealed keys; a removed member is a stranger ("unknown"). Any member that holds the key can answer (so the owner need not be online). The node loop issues a `key` job when it holds events of epoch e but no K_e, or sees the state epoch above its keyring (backoff like the other jobs).
   c. Observer (the human) = a member role: gets every epoch like anyone else.
4. Sending rule: a node never serves or sends an event of an encrypted thread in plaintext (only the genesis). `notify` carries ids only (unchanged).

## Failure / hostile cases to test
wrong key / wrong epoch / wrong thread (AAD), truncated / flipped ciphertext, nonce reuse detection is not possible (random) -> tested statistically only, padding bucket edges, envelope of one thread replayed into another (AAD), old epoch in flight after rotation, removed member asking for keys, member asking for keys of another thread, non-member with the ciphertext, plaintext downgrade (rejected), key file corruption / 0644 / symlink, LOCKED thread load, migration of a plaintext thread, crash between key creation and file rewrite, sealed key to the wrong recipient, sealed key replayed to another thread/epoch, joiner with a forged `joined` answer carrying garbage keys, size limits (envelope <= event cap + padding), junk counters (envelopes that do not open count toward the pull junk cap).

## Not in this step
Hiding ids/epochs from carriers (blind tags, spec 7.1 `t`), key rotation on a schedule (only on member_remove for now), forward secrecy, passphrase-protected keyring (the README says the key file is 0600 next to the data), public threads.

## REVISION 1 (Sansa's review [DONE] 7520a6bcbf12, : "direction is sound"; all five must-fixes accepted)
1. KEY ID = the id of the event that created the epoch, not the integer: epoch 0 = the thread (genesis) id; every later epoch = the id of the `member_remove` that bumped it. Helper `epoch_id(thread, admin_id)` walks the derived chain (no thread.py change: `states[admin_id]["epoch"]` already tells where the bump happened). Envelope field `ep` = that id. WHOEVER performs the removal (owner or the k admins) creates the key for it and keeps it. `key` answers only cover epoch ids on the ASKER's current derived chain at the server (never keys of abandoned branches); new members get all earlier epochs (history is visible to them: stated).
2. `join_request` is SIGNED by the joiner's sign key (domain "sigilnet/v1/join-request\0" over token, kex, onion, port, client_pub, name); the owner verifies before parking. The `key` op takes the asker's kex key from the `member_add` on the chain, never from the request. Sealed-key HKDF info = ephemeral pub || recipient kex pub || thread || key id; `key` responses are signed by the responder, the signature covers the sealed blobs.
3. Keys received are installed only if they OPEN at least one envelope of that epoch we already hold; otherwise they stay UNVERIFIED (replaceable, never used to encrypt); a verified key is never overwritten; `key` answers are accepted only from a responder that is a current member in OUR state.
4. Between a removal and the arrival of the new key an author never encrypts at the new epoch without the key and never falls back to the old key: the event is QUEUED (outbox) and `need_key` is raised. README: events authored before the author saw the removal stay readable to the removed member.
5. README wording: keys next to the data in one home protect against a non-member carrier and partial copies only; a backup of the whole home includes the keys.
Q2: a per-thread "encrypted" flag persisted in node.json (and, for new threads, cheap hardening: `enc` in the genesis is NOT done here: thread.py stays frozen) so a deleted/unreadable keyring makes the thread LOCKED (not readable, not accepting plaintext). Joiner: capsule enc=true but no keys in the signed `joined` answer -> refuse; keys present win over enc=false. Q3: `key` requires a non-removed member whose role is not guest; every refusal is the same "unknown". Q4: README and `capsule describe` say: title and member names of the genesis are visible to carriers. Q5: pending events whose admin_ref is unresolved at rest use the newest verified key; `ep` is outside the signature: a flipped `ep` fails AAD and counts as junk. Q6: Mirror gets a `codec` object in its constructor (default identity; one code path), the existing suites are parameterized to also run with the encrypting codec on private threads; tests for torn tails/offsets with encrypted lines and for LOCKED threads not being re-scanned on every refresh. Padding: a 4-byte length prefix inside the plaintext, verified on open.
BUILD ORDER: (a) envelope.py: keyring, epoch ids, seal/open, padding, ECIES (pure, tested first); (b) Mirror codec + LOCKED + migration; (c) sync `get`/pull + `key` op + node key job; (d) capsule: signed join_request, keys in the `joined` answer, `enc`; (e) CLI `envelope enable|status`, README; (f) parameterized suites, independent adversarial tester, mutation run, live test (needs the human's go).
